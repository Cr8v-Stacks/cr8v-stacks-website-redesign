The Challenge

WP Publishion AI is our own proprietary in-house AI content-writing tool for WordPress, built to draft fact-checked, SEO-rich articles directly inside the block editor. As our first core in-house product, we wanted to build a workspace interface that could demonstrate our AI design capabilities while solving publishing speed bottlenecks for large blog sites.

Designing a complex AI workflow requires clear visual hierarchy to prevent editor fatigue. The workspace had to accommodate LLM parameters panels (integrating Claude, Gemini, and OpenAI), Brave Search fact-verification fields, and generation tasks calendars in a single, user-friendly layout. We scoped this design system from a blank canvas to prepare for internal development.

The Solution

We built WP Publishion AI as a fully functional, production-grade content generation pipeline — not just a prototype. The system integrates multiple AI providers, runs automated fact-verification in the background, and publishes structured content directly into the WordPress block editor.

1. Multi-LLM API Integration & Prompt Engineering

We integrated Claude, Gemini, and OpenAI APIs into a unified prompt-routing layer. Users can select their preferred LLM, tune generation parameters (temperature, max tokens, system role), and queue multiple content generation tasks simultaneously. Each API call is managed by a backend task dispatcher that handles retries, rate limits, and model-specific payload formatting.

2. Background Fact-Verification via Brave Search

Generated content is automatically queued for fact-verification using the Brave Search API. A background worker dispatches verification requests against key factual claims in the draft, appending source annotations and confidence scores before returning the article to the editor — all without blocking the user's workflow.

3. WordPress Block Editor Integration & REST API Publishing

We built a custom WordPress plugin that exposes a dedicated sidebar panel inside the Gutenberg block editor. Content generated and fact-checked by the pipeline is injected directly into editor blocks via the WordPress REST API, allowing seamless single-click publishing with SEO metadata pre-filled.

Our Approach

We architected and deployed the full stack in a four-phase build cycle, moving from API integration scoping through to live sandbox deployment.

01
API Architecture & Routing Layer

We designed the multi-provider routing layer to standardize request/response structures across Claude, Gemini, and OpenAI, enabling provider-agnostic prompt dispatch and response normalization.

02
Background Task Queue Engineering

We built an asynchronous task queue system to handle content generation jobs, Brave Search fact-check requests, and re-verification retries — keeping the editor interface fully responsive during processing.

03
WordPress Plugin Development

We developed the custom Gutenberg sidebar plugin, wiring the pipeline outputs to block-editor-compatible data structures and REST API endpoints for seamless, one-click publishing into WordPress.

04
Sandbox Deployment & Testing

We deployed the fully functional sandbox environment — live and publicly accessible — to validate the end-to-end pipeline under realistic publishing conditions, iterating on prompt parameters and fact-check accuracy.
